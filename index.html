Tool library — category filters and live search across the modular toolbox

HandyTools

Engineering & utilities SaaS — own product, built solo
beta

PDF, image and OCR tools plus a full-screen Leaflet Surveyor Toolkit for Greek cadastral work, in English and Greek, with Free/Pro/Enterprise tiers enforced server-side through DRF permissions.

Background jobs: Celery/Redis pipelines for OCR and PDF conversion with bounded retries, late acknowledgement, time limits and atomic result writes. Uploads up to 50 MB are staged on disk and passed to workers by path, keeping them out of Redis messages.
Architecture: Framework-free, mypy-checked domain modules behind thin class-based DRF views. Coordinate conversions route through a single GGRS87 (ΕΓΣΑ87) pivot instead of pairwise transforms. Per-user quotas hold under concurrency with select_for_update row locks.
Quality: ~700 tests in GitHub Actions alongside ruff, mypy and a missing-migration check, with Docker images pushed to GHCR. Greek coordinate transformations (HEPOS, HATT) are tested to the millimetre against official values.
Status: 230+ commits since July 2025. A restricted beta is open to invited engineers while the build continues.

how-i-work/

Spec first

Larger features start as a design doc and a phased plan with explicit scope decisions, so trade-offs are made on paper before they're made in code.

AI-assisted, human-reviewed

Design docs and plans drive coding agents (Claude Code) for implementation, tests and security review. I review every change before it merges.

CI on every push

Django tests, ruff, mypy and a missing-migration check run on GitHub Actions; Docker images are built and pushed to GHCR.

Layered architecture

Framework-free, type-checked domain modules behind thin class-based views, so the business logic can be tested without the web layer.

I run what I ship

Docker Compose stacks on Hetzner Cloud: Gunicorn behind a shared Nginx proxy, Let's Encrypt TLS, loopback-only ports and memory limits.

Written runbooks

Deploy, backup and restore procedures are documented for every production app, so recovery doesn't depend on memory.
